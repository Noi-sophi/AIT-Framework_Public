# 編成（関手・変換）

## 0. 目的（1行）
- 旧・調整系を **deprecated** とし、長期変化（学習・劣化・再編）を「作動射の外」で扱うためのメタ概念を定義する。

## 1. 位置づけ（射影）
- 形式界: meta（主体射影を記述するための形式側）
- 対象: 主に主体射影（agent）のモジュールと作動射群

## 2. 基本対象
- モジュール: 状態束＋それを更新する作動射群（作動射がwriterを持つ）により定義される。  # 詳細は [モジュール(定義)](CANON/モジュール(定義).md)
- 作動射: 状態遷移の最小十分粒度。入力/参照/更新(writer)/出力を持つ。  # 詳細は [作動射(状態遷移射)](CANON/作動射(状態遷移射).md)

### 2.1 移行宣言（旧・調整系 deprecated → Exec-only）
- 原則：作動射は **Exec.*（実行状態）のみ**を読み書きする（Exec-only）。
- 旧：調整系は「作動射の癖」を状態として保持していた。
- 新：短期の可変は「作動射が変わる」のではなく、**別の作動射が出力する制御信号（値）**として表す（= output / message / event / Execへの書き込み）。
- 長期の変化（技能獲得・忘却・固定化・再編）は、編成関手 F と編成変換 η の適用として表す（下記）。

> 旧・調整系の語は当面の移行作業で残存し得るが、最終的に参照 0 件を目標とする。

### 2.2 短期変化（制御信号）
- 「短期で変わるパラメータ」は、作動射の属性や旧来の調整系として持たず、次のいずれかで表す：
  - (A) 別作動射の outputs として受け取る（push）
  - (B) Exec.* の共有状態（例：Exec.Control.*）に書き込み、それを reads する（pull）
- 典型：Exec 状態 → Control を出す → Control を参照してルーティング/選択 → 本体更新

> ここでの Control は「値」であり、作動射の入出力スキーマそのものを変えない（スキーマ変更は編成で扱う）。

## 3. 編成関手（Composition Functor）
### 3.1 定義（最小）
- 編成関手 F は「モジュール（またはモジュール群）を、別のモジュール（群）へ写す」操作として扱う。
- 直観: F は “作動射群の設計” を時間をかけて更新する（追加・削除・置換・内部パラメータ更新・合成/分解など）。

### 3.2 既定制約（運用）
- 既定では interface（入力/出力の形）は保つ（破る場合は明示的に「編成でスキーマ変更」と書く）。
- 実行（Exec.*）はオンライン更新（その時点の入出力・writer・アルゴリズムで状態遷移）を担当し、長期変化は F の適用結果として反映される。
- fast/slow は必須の軸ではない。必要なら「説明タグ」として付けるが、頻度や反映は schedule/window/execution で表す。

## 4. 編成変換（Composition Transformation）
### 4.1 定義（最小）
- 編成変換 η は、2つの編成関手 F,G のあいだの“対応づけ”として扱う（例：近似パラメータ列の更新、段階的移行、補間）。
- 直観: 「同じ目的の編成を別手続きでやったときの整合」を取るための写像。

## 5. 性質タグ（分類軸）
- scope: module | morphism_set | parameter
- effect: capability_up | capability_down | neutral
- change: param_only | add_remove_morphism | refactor_morphism | schema_change
- trigger: experience | time | instruction | anomaly
- reversibility: high | medium | low

## 6. 最小例（主体射影）
- スキル獲得: param_only → add_remove_morphism へ拡大（新しい作動射を導入）
- 忘却/劣化: capability_down + param_only（閾値の鈍化など）→ add_remove_morphism（作動射の消失）
- 固定化/自動化: refactor_morphism（複数作動射を合成して1つに圧縮）
