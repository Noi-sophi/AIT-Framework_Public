# 形式界（基底）

## 0. 位置づけ（最小 / meta）
- **形式界（meta）** は実在界（world）の射影ではない。実在界を「記述・検証・操作」するための **記号操作の界**である。
- 実在界は **物理射影 / 主体射影 / 社会射影** に分かれる（射影＝world側のみ）。
- 形式界は単一の「論理体系」ではなく、**記号体系（Kernel）の族**として扱う（自然言語、図式、コード、形式論理などを含む）。
- 実在界→形式界は **記述／記号化（Encode）** として書き、形式界→実在界は **適用／作用（Enact）** として書く。
  - 記号は直接 world を変えない。原則として **主体射影の作動射**（入力→内部更新→介入/発話）および **社会射影の流通・評価・許容域**を介して作用する。

---

## 1. 全体方針（最小 / meta）
### 1.1 「記号体系（Kernel）の族」
- 形式界は Kernel の集合 `K = {k}` で与える。
- 各 Kernel `k` は次の成分を持つ：
  - 字句：`U_k, Gate_k, Tok_k, Amb_k`
  - 構文：`AST_k`（抽象構文木の型。Kernelごとに異なってよい）
  - 意味：評価域 `V_k`（**凍結しない**）と評価 `Eval_k`
  - 結果：`EvalResult_k := (value ∈ V_k, source ∈ {world, theory})`

> `source` は必ず付与する。  
> - `world`：観測・計測・実行ログ等から来た生成物  
> - `theory`：仕様・辞書・文法・推論器・設計文書（AITF自身を含む）から来た生成物

### 1.2 凍結しないもの
- 評価域 `V_k` は固定しない（Heyting代数等は **Kernelの一例**に降格）。
- `Eval_k` は関数でも関係でもよい（非決定・曖昧性・候補集合を許す）。

### 1.3 凍結する最小規約
- **合成の許可条件（AND）**：合成/照合の“直結”を許すのは **同一 `source` かつ 同一 Kernel `k`** の場合のみ。
  - 同一 `source` かつ同一 `k` の `EvalResult_k` 同士は、Kernelが定める演算で合成してよい。
- **分岐（直結できない場合）**：
  - `source` が異なる（例：world vs theory）場合：`Compare_k` に回し、差分として保持する（合成しない）。
  - Kernel が異なる（k≠l）場合：まず `Translate_{k→l}` 等で Kernel を揃えてから合成/照合する（Kernel横断の直Compareは禁止）。

## 2. Kernel 共通骨格

### 2.1 字句基底（Lexical Base / meta）
- `U_k`：入力担体（文字列・トークン候補・記号候補・音声特徴・図形要素など）
- `Gate_k : U_k → {in, out, ?}`
  - `Tok_k := {u ∈ U_k | Gate_k(u)=in}`（扱う対象として取り込む）
  - `Amb_k := {u ∈ U_k | Gate_k(u)=?}`（**媒体側の未確定**：後段の意味未確定と区別）
- 目標：Amb を「失敗」ではなく **情報として保持**し、後段の候補生成に渡せるようにする。

### 2.2 構文基底（Syntax Base / meta）
- `AST_k`：Kernelごとの構文表現（例：文、式、図式、プログラムIR、対話行為タグ列…）。
- 運用上の既定：
  - Kernelが必要とする場合のみ「Closed」「Binder-free」等を採用する（**形式界全体の標準にはしない**）。

### 2.3 意味基底（Semantics Base / meta）
- `V_k`：Kernelの評価域（例：候補集合、確率分布、順位、型、制約集合、真偽値、スコア、手続き…）。
- `Eval_k`：`AST_k` と（必要なら）解釈を受けて `V_k` を返す。
- 返却は常に `EvalResult_k = (value, source)` とする。

---

## 3. 形式界↔実在界のインタフェース（往復）

### 3.1 記述／記号化（Encode / world→meta）
- `Encode_k`：world側の入力（観測・状態・制約・更新）から、Kernel `k` の記号を生成する写像（作動射として実装され得る）。
- 典型入力（射影別）：
  - 物理射影：計測値、イベントログ、制約（資源上限など）
  - 主体射影：観測/不一致/要求、内部状態の要約、発話意図
  - 社会射影：関係、規範、許容域、流通状況、評価

### 3.2 理論内生成（Derive / meta→meta）
- `Derive_k`：Kernel内の変換（推論、要約、整形、再記述、同値変形、候補生成など）。
- `source=theory` の生成はここに含める（辞書・文法・仕様・AITF文書）。

### 3.3 翻訳／射影（Translate / meta_k→meta_l）
- `Translate_{k→l}`：Kernel間の写像（例：自然言語→論理、図式→記述文、コード→仕様、仕様→テスト…）。
- 原則：Kernel横断の直Compare/直合成は禁止。必要なら `Translate_{k→l}` で同一 Kernel に揃えた後に、`Compare_l` / 合成を行う。

### 3.4 照合（Compare / meta）
- `Compare_k` は **同一 Kernel `k`** に限り定義する：
  - `Compare_k : EvalResult_k(world) × EvalResult_k(theory) → Diff_k`
- `Diff_k` の最小仕様（評価域 `V_k` が未凍結でも成立する最小）：
  - `Diff_k := (value_w, value_t)`  （ペアで保持するだけでもよい）
  - 任意：`label ∈ {match, mismatch, undecidable, incomparable}` を付与してよい
- Kernel が異なる場合（k≠l）は、`Translate_{k→l}` を介して同一Kernelに揃えてから Compare する。
- 目的：不一致を「破綻」ではなく、後段（主体の不一致入力、再質問、学習、社会的再調整）へ渡す。

### 3.5 適用／作用（Enact / meta→world）
- `Enact_k`：記号（または評価結果）が world 側の更新に接続される経路。
- 原則：
  - **物理射影**へは、主体射影の介入（作動射 outputs）を介して届く（操作、入力、制御など）。
  - **主体射影**へは、次のいずれかとして入る：
    - inputs（観測/要求/不一致としてのメッセージ）
    - reads（参照すべき資料・規範・辞書）
    - `Exec.Control.*`（短期の選択・モード・解釈器切替）
  - **社会射影**へは、発話/行為の流通・評価・許容域更新として入る（規範・期待・信用・制裁など）。

## 4. 解釈の揺れ：解釈器選択（agent / meta）
同一記号でも解釈が揺れる主因は、受け手が「どのKernel／どのAdapterで読むか」を状況依存で切り替えるためである。

### 4.1 封筒（Envelope）モデル（meta→agent）
受け手が入力として扱う単位を「記号列 `s`」ではなく、次で表す：
- `Envelope := <payload, sender, channel, time, thread/context, provenance-hints, ...>`

### 4.2 InterpretRouter（主体内の作動射）
- 入力：Envelope
- 参照：相手モデル（sender傾向）、状況モデル（話題/目的）、関係（信頼/権威/距離）、直近メモリ
- 出力（短期制御信号の例）：
  - `Exec.Control.Interpret.kernel_id`
  - `Exec.Control.Interpret.adapter_id`
  - `Exec.Control.Interpret.mode`（literal/ironic/technical/ritual など）
- 後段：選択された kernel/adapter で Decode/Eval を走らせる。

> 共有解釈は厳密には成立しないが、社会的相互作用（反復・教育・同調・規範）により、Router の選択分布が近づき「ある程度揃う」領域が生じる。

---

## 5. 具体例（短）

### 5.1 発話「やばい」（agent + social + meta）
- payload は同じでも、sender・channel・直前文脈で InterpretRouter が mode を切替し、意味候補と行動（Enact）が変わる。

### 5.2 自然言語→仕様→コード（meta↔meta↔world）
- Encode（観測/要求→文章）→ Derive（仕様化）→ Translate（仕様→コード）→ Enact（実行によりworld更新）
- Compare（実行ログ=world と仕様=theory の差分）→ 不一致として主体に戻る。

---

## 6. 一般語（まとめ）
- 形式界は「論理」ではなく「記号操作一般」。
- 記述（Encode）で world を記号へ写し、適用（Enact）で記号を world の更新回路へ接続する。
- 意味は記号に固定されず、Kernel/Adapter の選択（解釈器切替）と社会的条件で揺れる。
- その揺れを隠さず、候補・差分・制御信号として一次情報にする。
